# Review of docs/plan-app-store.md by gpt-5.6-sol

Date: 2026-09-29. One review of the finished draft, via `codex exec -m gpt-5.6-sol -s read-only --skip-git-repo-check --ephemeral` with the plan inline. Processing: section 14 of the plan.

1. **High — §1.1, §10 (data sources/legal):** `robots.txt` is not permission to scrape, and the plan acknowledges but defers the web-page terms question while making scraping the authoritative production source. The Lookup API’s promotional-content terms may also conflict with permanent caching and report embedding. **Fix:** make legal/terms validation an A0 gate; document permitted caching, display, attribution, retention, and redistribution. Until resolved, ship API-only or an explicitly experimental, user-supplied-page mode.

2. **High — §2 (Apple rules):** Several “enforced” interpretations overstate Apple’s text. Guideline 2.3.7 prohibits misleading/irrelevant metadata stuffing with trademarks and pricing; it is not accurately summarized as an absolute ban on all prices, app names, or trademarks in every screenshot. “First three count double” is an invented scoring rule, not an Apple rule, and search presentation varies by device/context. **Fix:** store exact rule scope and separate `hard prohibition`, `review risk`, `official guidance`, and `analysis heuristic`; label weighting as configurable methodology, not enforcement. Apple does confirm 2.3.3’s app-in-use requirement and current PPO constraints ([guidelines](https://developer.apple.com/app-store/review/guidelines/), [PPO](https://developer.apple.com/app-store/product-page-optimization/)).

3. **High — §3–4 (shared content-addressed library):** `library/apple/<hash of asset path>.json` creates a platform-specific URL index, not the required shared content-addressed library. URL changes can duplicate content, while one URL could theoretically change content. **Fix:** ingest every downloaded asset into the existing byte-SHA/content store; maintain Apple URL/storefront observations only as aliases pointing to that SHA. Platform belongs on provenance, never on asset identity or analysis identity.

4. **High — §4, §6 (false free reuse):** “Pixel-identical after scaling” conflicts with the reported mean difference of 0.1 and the glossary’s “pixels are identical.” Resampling and tolerant comparisons can collapse materially different text or small UI changes and incorrectly reuse paid analysis. **Fix:** reserve free reuse for decoded canonical-pixel equality or a rigorously lossless equivalence test. Treat near-identical images as a comparison tier requiring deterministic OCR/diff validation or confirmation.

5. **High — §4, §6 (tier classification):** A ≤20-bit perceptual-hash match does not establish “same screen, only new text/shape.” The calibration is just 32 hand-inspected pairs, includes a known false negative, and compares only within the same game. Changed characters, UI elements, offers, or composition could inherit an invalid anchor analysis. **Fix:** use pHash only for candidate retrieval; require geometric alignment plus masked pixel/feature differences, OCR/layout checks, and confidence thresholds. Ambiguous cases must be full analysis or explicit confirmation, with benchmark precision/recall targets.

6. **High — §6 (cost estimate):** The estimate classifies 234 items as cheap before the proposed classifier and reshaped comparison exist, includes known wrong API sets, and omits likely layout/crop work, OCR, matching calls, retries, report input growth, and provider price/version assumptions. “Free” also conflates no model charge with network/storage/runtime. **Fix:** present this as a provisional scenario, calculate from an executable dry-run manifest, show model/token/image assumptions and worst case (all uncertain items full analysis), and regenerate the quote immediately before approval.

7. **High — §3, §5 (opt-in semantics):** Four controls—global enabled, game selection, country selection, and report chip—have no defined union/intersection or fetch behavior. A user can apparently enable a report and trigger Apple reads despite one of the other scopes being off. **Fix:** define one effective-selection rule, e.g. project capability off by default, then explicit `(game, country)` pairs; every UI edits/previews that same set. The report builder may narrow it but never expand it silently.

8. **High — §1.3 (matching):** Persisting `none` per storefront can turn a transient search/API failure into permanent unavailability. Case-insensitive bundle matching and fuzzy seller comparison are insufficiently specified, and the hard-coded own-app ID bypasses verification. **Fix:** distinguish `not_found`, `unavailable`, `fetch_failed`, and `confirmed_none`; record evidence, source, timestamp, candidates, and recheck policy. Verify every selected track ID’s bundle, seller, icon, title, and storefront availability, including the project app.

9. **Medium — §3 (schema/migration):** Paths still use `<gl>-<hl>` although Apple language is separately modeled; two Apple localizations can collide. Optional `platform` also risks legacy code treating unknown/missing values inconsistently. “Older versions ignore the folder” is asserted without evidence, and a minor format bump may be unsafe. **Fix:** key Apple snapshots by storefront plus normalized Apple locale and track ID; add explicit schema versions and parsers; test downgrade behavior with actual old import code, or declare new archives unsupported by old versions.

10. **Medium — §3, §7 (media modeling):** Apple supports up to three previews per localization/device size, but the plan repeatedly models “a video,” estimates one poster per game/store, and uses screenshot-style slots without duration/source fields. Events are reported yet their artwork/text provenance, dedup, history, and analysis costs are undefined. **Fix:** model an ordered media union with multiple previews and separate event entities; specify poster/video metadata, fallback localization, provenance, and whether each asset enters costing.

11. **Medium — §7.3 (PPO/CPP mapping):** A Play “variant” does not mechanically map to an Apple treatment. Alternate icons must already exist in the binary; PPO localization and traffic constraints matter; CPP keywords can only be assigned from eligible approved keywords, not arbitrary inferred audiences. **Fix:** add feasibility checks and platform-specific card types. Mark unsupported ideas as creative recommendations, not executable PPO/CPP tests; include control, traffic allocation, minimum sample/likely duration, and icon-binary dependency.

12. **Medium — §8–10 (ordering/in-flight work):** A4 depends on unfinished text-comparison and layout work, while A0 duplicates Apple facts planned for the knowledge base; A3 combines fetching, UI, viewing, and dedup into one large milestone. **Fix:** first land shared schema/library primitives and the speed/layout dependencies; make the KB the single rule source before report prompts; split ingestion/dedup from UI. Add explicit merge points with cross-country, share/import, and report-schema branches.

13. **Medium — §9 (tests/PILLARS enforcement):** Tests do not cover transient failure versus unavailability, locale/path collisions, multiple videos, asset URL mutation, tolerant-dedup false positives, stale rule provenance, or every individual 2.3.3-violating recommendation. **Fix:** add adversarial fixtures and invariants: no paid reuse without validated equivalence, no Apple recommendation containing a title-art-only screenshot, no silent page-to-API downgrade, and no paid call without a fresh itemized approval.
