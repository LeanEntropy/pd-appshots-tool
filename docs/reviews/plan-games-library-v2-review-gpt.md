# Review: plan-games-library version 2 (gpt-5.6-sol, 2026-09-29)

Reviewer: gpt-5.6-sol via `codex exec -m gpt-5.6-sol -s read-only --skip-git-repo-check --ephemeral`, plan, user requirements and code facts passed inline (prompt: scratchpad games-lib/review-prompt.md). The single review of this version. Raw output below; outcomes are in the plan's "Review outcome (version 2)" section.

1. **High — §2.2 Texts / D3** — The plan does not satisfy “all texts (original + English).” Most analyses have no saved English translation; layer-diff covers only certain comparisons and country advice covers only the headline. “English not saved yet” documents missing data but does not meet the requirement. **Fix:** include translation generation/import in the milestone, with explicit approval/cost handling if it is paid, or obtain an explicit requirement change before implementation.

2. **High — §2.2 Focus band / D4** — `focusMatch.reason` is not a reinforcement field. Presenting it as “Reinforcement” can produce incorrect or unrelated content. **Fix:** add a dedicated reinforcement field to the layout schema/prompt, or derive reinforcement deterministically from headline/elements and label it as derived; do not relabel `focusMatch.reason`.

3. **High — §§0, 2.3, 12** — The claimed read-only behavior is internally contradictory. The Light-import button is said to “run” the existing full-size download, which performs network work and writes originals/cache data, while the plan says there are no downloads and the index is the only written file. **Fix:** state the actual mutations and network behavior, identify the exact existing action/endpoint, its scope, authorization, and progress states, and remove the false read-only claims.

4. **High — §§2.2 History, 5** — “Other readings … under other settings” cannot be implemented through `readStoredRecord`, which intentionally restricts a project to its own analysis key or earlier unproven record. The plan provides neither a permitted index nor an access rule for these records. **Fix:** restrict History to records legally visible through the selected project, or add a Storage-backed, policy-aware history API and specify exactly which records may be exposed.

5. **High — §§2.2 Footer, 5** — The promised cost/provenance wording is not supported as written. `paidBy` contains only `{projectId, usd|null}`, not a payment date, and summing every finished attempt may include retries or work unrelated to the displayed record. **Fix:** define which attempt IDs/stages belong to the selected record, derive the displayed total from those only, and omit the payment date unless a real persisted source supplies it.

6. **High — §§2.1, 6** — Invalid but well-formed context is silently discarded and replaced by another appearance/project. A shared URL can therefore display a different country, position, or project than its address claims, which is misleading for a context-sensitive page. **Fix:** distinguish missing context from mismatched context: choose defaults only when fields are absent; return a clear 404/invalid-context state or an explicit fallback requiring acknowledgment when supplied context does not match.

7. **Medium — §§2.1, 2.2, 6** — The image page is global, but its image URL must use the selected project’s reference-gated `/p/<id>/images/...` route. The plan does not define what happens if the selected project has only a thumbnail, is archived, disappears between HTML and image requests, or the project selector changes. **Fix:** make the resolved referencing project part of the server-built view, generate only its authorized original/thumbnail URL, define the fallback behavior, and test project removal and selector changes.

8. **Medium — §§3, 4; standing flag rule** — The directory’s flag-only chip row violates the standing rule that flags appear only next to a country name in a title or heading. Calling them “meta chips” does not override that rule. **Fix:** use country-name chips without flags, or make each country entry a genuine heading/title containing both the name and flag.

9. **Medium — §9 Wireframe component** — The proposed numbered mode changes both in-flight wireframe files immediately after merge and substantially changes `parts` semantics from “only boxes with more to say” to every shape. That is a contract change, not merely a display option, and may affect existing popover callers and snapshots. **Fix:** define a separate adapter/view model for the image page where possible; otherwise version the component API and add regression tests proving the popover output and existing `parts` consumers remain unchanged.

10. **Medium — §§7.1, 7.3** — The global image-use map is invalidated by the workspace-wide `dataStamp`, so any unrelated write can force rereading every project’s `refs.json` on the next image request. This conflicts with the cold-page target on large workspaces. **Fix:** cache the map using refs-specific fingerprints or update it incrementally from changed projects; measure worst-case invalidation, not just a warm process.

11. **Medium — §7.3 Freshness** — The persisted index strategy relies partly on size/time metadata and “marker touches,” but the plan does not establish Storage methods for timestamps or marker observation. Implementing these checks directly with filesystem APIs would violate the no-direct-fs rule. **Fix:** name the existing Storage operations that provide these facts, or extend the Storage interface first and test cross-process writes and restart freshness.

12. **Medium — §§2.2, 7.1** — “Same picture, new text” and “same screen uploaded twice” can require checking many pair keys. The plan says only stored results are read but does not define candidate enumeration, bounds, or how the page distinguishes “not a match” from “not computed yet.” A naïve implementation becomes quadratic and may mislabel incomplete data. **Fix:** consume a stored per-deck result index/status, or define bounded candidate generation and explicit `matched / checked-no-match / pending` states.

13. **Medium — §§2.2, 5** — Analysis date is unspecified. `record.updatedAt` may represent review, adjudication, migration, or another later update rather than when the analysis was produced. **Fix:** define the exact persisted timestamp used for “Analysed,” and show separate produced/reviewed dates when those events differ.

14. **Medium — §§6, 11 Security** — “Text is escaped” and `textContent` cover only part of the XSS surface. Server-rendered JSON bootstrap data, query-built links, attributes, game names, store text, and `appId` path segments also need context-specific encoding; `</script>` is especially relevant when embedding JSON. **Fix:** specify one safe serialization/escaping path, use `encodeURIComponent` for every URL component, avoid HTML-string insertion in client scripts, and add payload tests for quotes, ampersands, Unicode, `javascript:`, and `</script>`.

15. **Low — §§0, 8, 10 App Store conflict** — “Whichever lands second adds `platform`” is not a workable conflict or migration strategy. Both plans touch source/deck schemas and URL identity, while this plan otherwise starts from post-wireframe master only. **Fix:** establish an explicit dependency or shared schema change, include migration/backward-compatibility tests for sources without `platform`, and define whether platform is part of game-page identity and indexing.
